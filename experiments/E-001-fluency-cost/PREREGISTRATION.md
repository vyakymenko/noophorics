# E-001 — The Cost of Fluency

**Status:** pre-registered, not yet run
**Registered:** 2026-07-28
**Attacks:** [L5](../../theory/laws.md#l5) (fluency inflates phantom agreement),
[L6](../../theory/laws.md#l6) (optimal encoding is contrastive)

> This file was committed before any data existed. If results appear in a
> later commit that contradict the hypotheses below, the hypotheses lose. That
> is the arrangement.

---

## 1. Question

Two messages of **equal token cost**, written by the **same sender**, about
the **same source material**, differing only in encoding style:

- **NARRATIVE** — fluent, well-organized prose explaining the rules.
- **CONTRASTIVE** — terse boundary cases, exclusions, and "do not" clauses.
  No prose connective tissue.

Which transfers more understanding, and which produces more confidence that it
did?

L5 and L6 jointly predict the uncomfortable answer: **the encoding that
transfers best is the one that feels worst.**

---

## 2. Hypotheses

| ID | Hypothesis | Predicted direction | Kills |
|---|---|---|---|
| **H1** | Contrastive encoding achieves higher transfer fidelity at equal cost | `F*(K) > F*(N)` | L6 if false |
| **H2** | Narrative encoding produces higher phantom agreement | `Φ(N) > Φ(K)` | L5 if false |
| **H3** | Contrastive encoding is more efficient | `η(K) > η(N)` | — (secondary; follows from H1 when costs match) |

**H2 is the load-bearing one.** H1 alone would be a useful engineering result.
H1 and H2 together are the claim that subjective confidence in a handoff is
*anticorrelated* with its quality — which, if it holds, is the reason this
field should exist.

---

## 3. Design

### 3.1 Domain

A fictional funding-eligibility rulebook: **The Kestrel Fellowship**
([`source-spec.md`](source-spec.md)). Fictional by design — no prior knowledge
can substitute for the transfer, so the receiver's baseline is a genuine
zero-information prior rather than a recall of training data.

Ten rules with deliberately awkward structure: an overriding rule (R7), a
partial-satisfaction rule for joint applications (R5), a scoped exemption
(R6, which exempts one rule and no others), an asymmetric auto-fix (R9,
which rescues under-budget but not over-budget), a clock-reset interaction
(R10 → R3), and inclusive/exclusive boundaries that differ between rules.

These are precisely the features a narrative summary drops and a contrastive
brief keeps. That is the point: the domain is built so the two encodings can
disagree.

### 3.2 Probe measure

`KESTREL-34` — 34 decidable cases, three-way answer space
(`ELIGIBLE` / `INELIGIBLE` / `ADJUSTED`), each with a ground-truth key
derivable from the spec. See [`probes.json`](probes.json).

Class balance: 13 ELIGIBLE, 18 INELIGIBLE, 3 ADJUSTED. A receiver defaulting to
the majority class scores 0.53 accuracy, which we note because it *deflates*
the measured prior gap `D_prior` and therefore makes the fidelity denominator
smaller and the test **conservative** — an artifact that works against our
hypotheses, not for them. Admissibility is checked at runtime and the run
aborts if the gap does not clear the noise floor.

### 3.3 Conditions

| Condition | Receiver's context | Purpose |
|---|---|---|
| `PRIOR` | nothing | establishes `D_prior` |
| `NARRATIVE` | `m_N` | treatment |
| `CONTRASTIVE` | `m_K` | treatment |
| `CEILING` | the full source spec | upper reference: what a lossless channel achieves |

`CEILING` is not a control — it is the empirical ceiling. If `CEILING` does not
reach high fidelity, the probe measure or the sender is broken and the run is
void. This is the experiment's own sanity check on itself.

### 3.4 Cost control

Both messages are generated by the same sender under a **350-token budget**,
stated in the generation prompt. Actual cost is measured after the fact with
the receiver's tokenizer and reported. If the realized costs differ by more
than 15%, H1 is evaluated on `η` rather than raw `F*`, and this substitution
is noted in the results — it is not a free choice made after seeing the
outcome.

### 3.5 Parameters

| Parameter | Value |
|---|---|
| Sender model | `claude-opus-5` |
| Receiver model | `claude-opus-5` |
| Samples per probe `n` | 6 (even, so it splits into two independent halves for the floor) |
| Effort | `low` (probe answering) |
| `ε` (admissibility) | 0.02 |
| Message budget | 350 tokens |

Sender and receiver are the same model on purpose: it isolates the *encoding*
variable from the prior-mismatch variable. Cross-model transfer is E-003's job,
not this one's.

## 4. Analysis plan

Fixed before data collection.

1. Compute `D_self` for sender and receiver from two independent sampling
   passes; derive `D_floor`.
2. Check admissibility: abort if `D_prior − D_floor ≤ ε`.
3. Compute `F*` for each condition, floor-corrected, unclipped below zero.
4. Compute `Â` and, for the two treatment conditions, `Φ` from sender and
   receiver claims elicited **before** either sees the probe results.
5. **Significance:** paired permutation test on per-probe divergence
   differences between NARRATIVE and CONTRASTIVE, 10,000 permutations,
   two-sided. Pure-Python implementation, seeded, no external dependencies.
6. Report `α = 0.05` for the primary comparisons (H1, H2). No correction
   applied across H1/H2 because they are separate hypotheses about separate
   quantities, not multiple tests of one.

### 4.1 Declared limitations

Stated now so they cannot be presented as discoveries later:

- **One domain, one model pair, one run.** This is a pilot. Whatever it finds
  is suggestive and nothing more.
- **34 probes gives limited power.** A small true effect will not be detected.
  A null result therefore does *not* refute L5 or L6; it fails to support them.
- **Claim elicitation is itself a noophoric act** and may be biased by how the
  question is phrased. The elicitation prompt is fixed in
  [`runner.py`](runner.py) and identical across conditions, but this is
  mitigation, not a solution.
- **Sender competence is a confounder.** If the sender misunderstands the
  spec, both messages are bad in a correlated way. Sender accuracy against the
  key is reported as a gate: below 0.85, the run is void.

### 4.2 Promotion criteria

For E-001 to promote L5 or L6 from `conjectured` to `supported`:

- the predicted direction holds, **and**
- `p < 0.05` on the permutation test, **and**
- `CEILING` fidelity `> 0.7` (the channel demonstrably works), **and**
- sender accuracy `> 0.85` (the sender demonstrably understood).

All four, or the law stays conjectured. A result that meets three of four gets
written up as a null with the failing gate named.

## 5. What each outcome means

| Outcome | Reading |
|---|---|
| H1 ✓, H2 ✓ | Both laws survive. The comfortable encoding is the worse one. Strongest available support for the program. |
| H1 ✓, H2 ✗ | Contrastive transfers better, but fluency does not inflate confidence. L6 supported, L5 wounded — and the field's motivating pathology weakens. |
| H1 ✗, H2 ✓ | Encoding form does not matter for fidelity but does for confidence. L6 refuted, L5 supported. Would refocus the program entirely onto Φ. |
| H1 ✗, H2 ✗ | Both refuted in this domain. Report it, mark both laws `contested`, and design E-001b in a domain with more interacting constraints before concluding anything general. |

A null result is publishable here and will be committed with the same
prominence as a positive one.

## 6. Reproduction

```bash
python3 experiments/E-001-fluency-cost/runner.py --dry-run   # pipeline check, no API calls
python3 experiments/E-001-fluency-cost/runner.py --samples 6 # real run
```

Results land in `experiments/E-001-fluency-cost/results/` as timestamped JSON
carrying every field of the reporting standard
([definitions.md §7](../../theory/definitions.md#7-reporting-standard)),
including the generated messages verbatim, so any claim in this repository can
be recomputed from the raw record.
